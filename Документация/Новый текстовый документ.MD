3D-моделирование Sol — рабочий процесс и инструменты

Зачем нужен этот документ

Этот документ фиксирует рабочий способ 3D-моделирования, который мы проверили в чате на нескольких экспериментах: terrain Ханты-Мансийска, часы, автомобиль по чертежу и шприцы.

Главная цель — чтобы в новом чате не приходилось заново выяснять, что Sol умеет делать с 3D-геометрией, какими способами это можно делать и какие ограничения есть у каждого способа.

Это отдельный workflow. Он не является Astro Modeler и не зависит от него.

Главное: Sol может создавать 3D-геометрию без открытого Blender

Для многих задач Blender вообще не нужен на этапе построения модели.

Рабочая схема, которую мы уже использовали:

Пользователь даёт описание, референс, чертёж или существующий 3D-файл.

Sol анализирует форму и разбивает объект на детали.

Геометрия строится процедурно в Python как вершины, рёбра и грани.

Результат записывается прямо в 3D-файл, чаще всего OBJ.

Пользователь импортирует OBJ в Blender и визуально проверяет результат.

Следующая итерация делается по конкретным замечаниям.

То есть Blender может использоваться просто как просмотрщик и место для ручной доводки.

Blender «за кадром»

В обычном чате Sol не имеет гарантированного постоянного доступа к интерактивному Blender UI и не должен делать вид, что видит открытую сцену, если такого инструмента реально нет.

Есть два разных режима:

Без Blender — Sol самостоятельно вычисляет геометрию и пишет OBJ/STL/PLY и другие подходящие форматы.

Headless/background Blender — возможен только если в конкретной рабочей среде реально доступен исполняемый Blender. Тогда Blender можно запускать командной строкой без окна и выполнять Python-скрипт через blender --background --python ....

Для наших текущих экспериментов наиболее надёжный путь — прямое процедурное создание геометрии без Blender.

Основные инструменты

Python

Используется для:

расчёта координат вершин;

построения полигонов;

симметрии;

копирования одинаковых деталей;

интерполяции форм;

цилиндров, труб, колец, фасок и других примитивов;

чтения карт высот;

генерации больших terrain-сеток;

записи OBJ/MTL;

анализа существующих 3D-файлов.

Большое число вершин не обязано занимать контекст разговора: массивы вычисляются программно и записываются сразу в файл.

OBJ / MTL

OBJ сейчас — основной рекомендуемый рабочий формат.

Он удобен тем, что структура простая:

v x y z — вершина;

f ... — грань;

o Name — имя объекта;

g Name — группа;

usemtl — материал.

Это позволяет генерировать модель без Blender и давать каждой детали понятное имя.

Поддерживаемые 3D-форматы

OBJ / MTL

Лучший текущий формат для:

статической геометрии;

процедурной генерации;

terrain;

hard-surface болванок;

именованных деталей;

обмена с Blender.

STL

Подходит для:

3D-печати;

цельных mesh;

простого обмена без материалов.

Можно создавать и читать программно.

PLY

Подходит для:

сканов;

point cloud;

mesh с vertex color;

промежуточных данных.

Можно обрабатывать программно.

glTF / GLB

Подходит для современных сцен и материалов.

Работа возможна, если в среде есть подходящие библиотеки. Для наших процедурных черновиков OBJ пока проще и надёжнее.

FBX

FBX — более сложный бинарный формат.

Мы уже проверили, что Sol способен:

определить бинарный FBX;

читать его служебную структуру;

видеть Geometry, Model, Objects;

определить, попала ли реальная геометрия в экспорт;

при наличии подходящего парсера извлекать mesh, имена и трансформы.

Для прямой генерации OBJ пока удобнее.

BLEND

.blend можно частично анализировать программно.

Но полноценное чтение и редактирование всей Blender-сцены без Blender нельзя считать гарантированным рабочим методом.

Если Blender доступен в среде, надёжнее использовать его в background-режиме через Blender Python API.

Симметрия

Для симметричных объектов лучше строить одну сторону и отражать её математически.

Повторяемые детали

Один винт, колесо, кнопка или другое повторяющееся изделие сначала доводится отдельно, затем копируется.

Принцип: сначала один хороший master, потом array/copy.

Boolean

Boolean можно делать:

через Blender Python API, если Blender реально доступен;

через вычислительную mesh-библиотеку, если она есть в среде.

Для повторяющихся задач лучше создать отдельный проверенный boolean.py, а не каждый раз заново придумывать логику.

Bevel / фаски

Фаски лучше строить через дополнительные контурные лупы.

Вместо одного грубого скоса:

основной контур;

offset;

2–4 ряда геометрии на фаске;

заданный радиус или ширина.

Как лучше давать входные данные

Один перспективный референс

Подходит для быстрой болванки и простого ассета.

Недостаток: скрытые формы и глубину приходится угадывать.

Ортографические проекции

Гораздо лучше:

front;

side;

top;

rear при необходимости.

По ним можно строить форму как систему сечений.

Обведённые силуэты

Очень полезны:

внешний контур;

внутренние отверстия;

оси;

центры;

линии разделения;

зоны фасок;

направление экструзии.

Даже грубая пользовательская обводка может быть ценнее красивого, но неоднозначного референса.

Размеры

Если известен хотя бы один реальный размер, остальные можно масштабировать относительно него.

Правильный порядок сложного моделирования

Разбить модель на детали.

Зафиксировать оси и масштаб.

Построить главный корпус.

Сверить силуэт.

Исправить пропорции.

Выбрать одну сложную повторяемую деталь.

Довести её отдельно.

Размножить.

Добавить фаски, посадочные места, панели и углубления.

Сохранять понятные имена объектов.

Принцип: одна деталь — один фокус внимания.

Имена объектов

Рекомендуемые имена:

BODY_MAIN

BEZEL_MAIN

SCREW_MASTER

SCREW_POCKET_01

WHEEL_MASTER

WINDOW_FRONT_L

PLUNGER

BARREL

Это позволяет в новом чате дать точную команду:

Измени только BODY_MAIN. Остальное не трогай.

Оси и координаты

Перед началом всегда фиксировать:

X / Y / Z;

где перед;

где верх;

плоскость симметрии;

единицы.

Пример автомобиля:

X — длина;

Y — ширина;

Z — вверх;

Y=0 — центр симметрии.

Пример шприца:

X — вдоль шприца;

игла — -X;

плунжер — +X.

Terrain

Рабочая схема:

получить DEM/heightmap;

декодировать высоты;

построить регулярную сетку;

убрать шум;

при необходимости усилить Z;

записать mesh в OBJ.

Важно отличать:

интерполяцию уже имеющейся сетки;

получение реально более детального DEM.

Интерполяция увеличивает число полигонов, но не создаёт новой достоверной информации.

Часы

По одной фотографии можно получить узнаваемую болванку, но для точного промышленного силуэта нужны дополнительные проекции, силуэты и размеры.

Машина

Несколько ортографических проекций дают гораздо более управляемый результат. Кузов удобно строить loft-ом из симметричных сечений.

Шприц

Очень удобен для процедурного моделирования:

полый цилиндр;

конические переходы;

фланец;

игольный узел;

отдельный плунжер.

Базовый протокол для нового чата

В новом чате достаточно дать ссылку на репозиторий и сказать:

Прочитай документацию по workflow 3D-моделирования Sol. Работаем процедурно. Не угадывай доступ к Blender. Сначала изучи существующую модель, имена объектов, оси и сохранённый скрипт. Затем измени только указанную часть.

Текущий вывод

Sol можно использовать не только как помощника, который пишет код для Blender, но и как самостоятельный процедурный генератор 3D-геометрии.

Наиболее надёжный текущий путь:

референс / чертёж / размеры → анализ формы → Python → именованные mesh-объекты → OBJ/MTL → проверка в Blender → итерация.

По мере развития репозитория этот путь можно расширять собственной библиотекой инструментов: boolean, bevel, mirror, loft, sweep, terrain и FBX-анализ.
